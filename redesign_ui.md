# Tanisha Pritha portfolio: UI redesign specification

## 1. Core direction

The existing content and positioning are good. The problem is the visual presentation.

Do not redesign the messaging from scratch.

Do not turn the site into a SaaS landing page.

Do not make it look like an AI dashboard.

Do not make it look like a generic developer portfolio.

The target is a high-end personal software portfolio / personal studio.

The visual feeling should be:

- Editorial
- Art-directed
- Premium
- Technical without being nerdy
- Confident
- Human
- Clean
- Slightly experimental
- Extremely readable
- Conversion-focused

Think of a designer portfolio or creative director portfolio that happens to belong to a very technical software builder.

The website itself should demonstrate taste.

The design should make someone think:

"She clearly knows how to build things, but she also knows how to present them."

---

# 2. Design principles

## Rule 1: No fluff

Every visible element needs a job.

Remove anything that exists only because it looks like a portfolio template.

No:

- Decorative dashboards
- Fake statistics
- Unnecessary badges
- Giant technology walls
- Excessive labels
- Fake testimonials
- Fake client logos
- Random animations
- Huge empty sections with no purpose
- Excessive cards
- "AI" decoration
- Generic stock illustrations

Use enough content to sell the capability and establish trust.

Nothing more.

## Rule 2: Typography does most of the work

Use typography as the primary visual element.

The hero headline should be large and editorial.

Recommended pairing:

- Strong modern serif for major display headlines
- Clean sans-serif for body, navigation, metadata and UI

If the existing stack makes a different pairing more practical, use a similarly high-quality editorial type system.

Do not use monospace as the dominant font.

Monospace can appear sparingly in technical areas.

## Rule 3: Spacious, not empty

Use generous spacing around important content.

Do not create huge vertical gaps simply to make the page longer.

Every section should have a clear visual purpose.

## Rule 4: One visual language

Use:

- Warm off-white / cream
- Near-black
- Muted gray
- One strong accent, preferably orange-red
- Optional restrained green only for availability

Do not use the current neon blue / cyber aesthetic.

Do not make every component colorful.

Accent color should be used for emphasis, interaction and small visual details.

# 3. Overall page structure

The homepage should feel like an editorial long-form portfolio.

Recommended order:

1. Navigation
2. Hero
3. Problem selector
4. Solutions
5. Selected work
6. Existing workflow / integrations
7. How I work
8. Technical depth
9. About
10. Final CTA
11. Footer

Do not make every section look like a collection of cards.

Alternate between:

- Large typography
- Editorial grids
- Image / project compositions
- Dark technical section
- Simple lists
- Strong CTA areas

This creates rhythm.

# 5. Hero

The hero is the most important visual change.

Do NOT use the existing architecture dashboard as the main hero visual.

The hero should feel like a creative portfolio introduction.

## Layout

Desktop:

Two-column composition.

Left:
Text and CTA.

Right:
A strong visual / portrait / art-directed project composition.

If a suitable personal image already exists in the repository, use it.

If there is no suitable personal image, do NOT invent fake credentials or fake photography. Use an abstract visual composition based on the actual work.

The visual should feel editorial rather than like a product screenshot.

## Copy

Use the existing strong positioning:

"AI + SOFTWARE BUILDER"

"I turn business problems into working software."

Supporting copy should stay concise:

"AI agents, custom applications, automation, AI systems, backend infrastructure and integrations. From a fast prototype to a complete intelligent system, I build what your business actually needs."

Primary CTA:

"Tell me what you're building"

Secondary CTA:

"See my work"

Small supporting line:

"Don't have a technical spec? That's fine. Start with the problem."

Availability can appear subtly:

"Available for new builds"

Do not overload the hero with technical terminology.

## Visual treatment

The headline should occupy significant visual space.

Use a serif display face or similarly expressive typeface.

Highlight only a small portion of the headline with the accent color if appropriate.

A subtle hand-drawn / editorial accent can be used under or around one phrase, but it must be restrained.

The hero should feel designed, not decorated.

# 17. Responsive design

Mobile is a first-class design target.

Required widths:

375px
390px
430px
768px
1024px
1440px
1920px

Mobile must have:

- Clear readable text
- No horizontal scrolling
- Large tap targets
- Comfortable spacing
- Simple navigation
- CTA accessible without hunting
- No microscopic technical diagrams
- No dense grids
- No text overflowing
- No oversized hero that pushes useful content too far down

Hero on mobile should stack:

Headline
Description
CTA
Visual

The visual can move below the copy.

Problem selector should become a clean vertical or horizontally scrollable interaction.

Solutions should become a vertical editorial list.

Projects should become large single-column showcases.

Technical diagrams should simplify on mobile.

# 18. Typography requirements

This is critical.

The site must remain readable.

Body text should never be tiny.

Do not use 10px or 11px body copy.

Suggested ranges:

Desktop body:
16 to 19px

Mobile body:
16 to 18px

Navigation:
14 to 16px

Major display headline:
56 to 88px desktop depending on viewport

Mobile display headline:
42 to 58px depending on viewport

Section headings:
40 to 64px desktop

Mobile section headings:
32 to 44px

Small labels:
12 to 13px, only where genuinely useful.

Prioritize readability over fitting more information.

---

# 19. Layout system

Use a consistent editorial grid.

Desktop:

Max width around 1400px.

Generous horizontal margins.

Use a 12-column or similarly flexible grid.

Do not center everything.

Use asymmetry intentionally.

Some sections can have:

Text on left
Visual on right

Others:

Visual on left
Text on right

Some full-width sections.

This should make the page feel art-directed.

---

# 20. Cards

Cards are allowed but should not dominate.

Use cards only when they improve scanning or interaction.

Avoid:

Card inside card
Card inside card inside card

Use flat sections, borders, large type and whitespace wherever possible.

---

# 21. Motion

Use subtle motion.

Good:

- Fade / reveal
- Small image movement
- Underline movement
- Hover transitions
- Section entrance
- Smooth scrolling
- Subtle cursor interactions

Bad:

- Constant floating
- Excessive parallax
- Glowing objects
- Large bouncing elements
- Long loading animations
- Animation on every card

Support reduced motion.

---

# 22. Visual texture

The references suggest a creative/art-directed quality.

Use texture carefully.

Potential elements:

- Very subtle paper grain
- Thin rules
- Editorial underlines
- Hand-drawn accent marks
- Cropped photography
- Black-and-white imagery
- Occasional oversized typography
- Asymmetric image placement

Do not use all of them at once.

The design should feel intentional.

---

# 25. Conversion hierarchy

The page should answer these questions in order:

1. What does Tanisha do?
2. Can she solve my problem?
3. What exactly can she build?
4. Can she work with my existing workflow?
5. Has she built serious things?
6. Does she understand the technical side?
7. How do I contact her?

If a section does not help answer one of these, remove it.

---

# 27. Final quality bar

The design should be:

Sexy through composition, not decoration.

Professional through restraint, not corporate styling.

Technical through real proof, not buzzwords.

Creative through art direction, not random graphics.

Clear through hierarchy, not by removing useful information.

Conversion-focused without feeling salesy.

Every element should earn its place.

The goal is not to impress people with how much the website contains.

The goal is to make the right person think:

"I have a problem. She can probably build the solution. I should talk to her."

# Website Redesign Specification

## 1. Purpose

This website is not a traditional developer portfolio.

Its job is to turn visitors into conversations.

The visitor should leave thinking:

> I have a problem. Tanisha can probably figure out how to build the solution.

The site should sell capability first and use projects as proof.

Primary conversion actions:

- Book a call
- Schedule an appointment
- Send an email
- DM on X/Twitter
- Message on LinkedIn
- Start a project conversation

Secondary goal:

- Demonstrate serious engineering depth to technical visitors.

---

## 2. Positioning

### Primary

**I turn business problems into working software.**

Supporting message:

**AI agents, custom apps, automation, AI systems, backend infrastructure and integrations.**

Important supporting idea:

**You don't need to know what technology you need. Start with the problem.**

The positioning should feel like a capable builder who can understand an ambiguous problem, determine the right solution, build it, integrate it into existing workflows, and ship it.

Do not repeatedly use "independent developer".

Do not present Tanisha as a generic freelancer.

Do not present the site as a software agency.

---

## 3. Audience

### Business / founder visitor

Needs to understand:

- What can she build?
- Can she solve my problem?
- What exactly would I get?
- Can this work with my current tools?
- Can I talk to her without having a technical specification?

### Technical visitor

Needs to discover:

- Agents
- RAG
- Memory
- Tool calling
- APIs
- Async systems
- Databases
- Queues
- Background workers
- Evaluation
- Observability
- Security
- Deployment
- CI/CD
- System design

Use progressive disclosure.

Simple explanation first. Technical depth second.

---

## 4. Core UX model

Do not organize the website around:

About -> Skills -> Projects -> Contact

Organize it around:

**Problem -> Solution -> What you get -> Existing workflow -> Proof -> Technical depth -> Conversation**

Projects are evidence, not the main product.

## 24. Visual system

Use a premium editorial/product aesthetic.

Priorities:

1. Typography
2. Spacing
3. Information hierarchy
4. Interaction
5. Technical diagrams
6. Subtle motion

Avoid:

- Excessive gradients
- Excessive glassmorphism
- Generic AI imagery
- Stock photography
- Giant glowing robots
- Cliché SaaS visuals
- Excessive animations

- 768px

Requirements:

## 27. Motion

Use subtle motion only.

Good:

- Card hover states
- Small button transitions
- Section reveals
- Workflow animation
- Architecture node reveals
- Page transitions

Bad:

- Constant floating objects
- Slow scroll-jacking
- Heavy parallax
- Decorative animation everywhere

Performance comes first.

"Cutting-edge AI solutions for digital transformation."

## 35. Design test

Review the completed site as two people.

### Founder test

After 15 seconds:

Can they explain what Tanisha does?

After 60 seconds:

Can they identify something they could ask her to build?

Can they contact her without preparing a technical brief?

### Senior engineer test

After exploring Work / Under the Hood:

Does the site demonstrate real engineering?

Does it show systems rather than buzzwords?

Does it show architecture and engineering judgment?

If either test fails, revise the UX.

---

## 36. The final feeling

The website should communicate:

**Bring me the problem.**

Not:

**Look at my projects.**

The website is a sales and trust layer around the technical ability.

The projects prove it.

The solutions explain it.

The technical breakdowns validate it.

The CTA turns it into a conversation.
